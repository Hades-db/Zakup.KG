# База данных Zakup.KG

PostgreSQL 16. Подходит и для своего сервера, и для Supabase: схема `zakup`, без расширений, только встроенные функции.

```
psql -d zakup -f db/schema.sql   # таблицы, правила, представления, доступ
psql -d zakup -f db/seed.sql     # демо-данные из макета
```

## Таблицы

| Раздел | Таблицы | Что хранит |
|---|---|---|
| Команда | `staff` | сотрудники Zakup.KG: вход по номеру телефона, пароль и код из приложения-аутентификатора; роли owner / support / moder / dev |
| Компании | `companies` | магазины и поставщики: ИНН (14 цифр), адрес, телефон, статус pending / ok / rejected / blocked с причиной |
| Пользователи | `users`, `sessions` | владельцы и доставщики, вход по телефону; сеансы для «Завершить сеансы» |
| Изменение данных | `company_change_requests` | правка названия, ИНН, адреса и телефона из профиля; действует после одобрения в админке |
| Пароли | `password_reset_requests` | заявки «Забыли пароль?», пароль выдаёт администратор |
| Каталог | `categories`, `products`, `product_photos`, `cart_items` | товары поставщиков, фото 2–5, корзина магазина на сервере |
| Заказы | `orders`, `order_items`, `order_events` | заказ, позиции со снимком цены, история статусов |
| Накладные | `invoices` | создаются при принятии заказа, реквизиты и позиции фиксируются |
| Уведомления | `notifications`, `push_campaigns` | колокольчик в приложении и рассылки из админки |
| Поддержка | `support_tickets`, `ticket_messages`, `data_requests` | чат поддержки, запросы по персональным данным |
| Документы | `documents`, `document_versions`, `document_acceptances` | оферта, соглашение, политика; кто какую версию принял |
| Настройки | `feature_flags`, `reject_reasons` | переключатели в «Технике», причины отказа |
| Журнал | `audit_log` | действия сотрудников, записи нельзя изменить или удалить |

## Правила, которые держит сама база

- Регистрация создаёт компанию в статусе «На проверке». Войти нельзя, пока администратор её не подтвердит (`login_check`).
- Один номер телефона — один действующий аккаунт.
- Изменения данных компании применяются только после одобрения (`admin_decide_change`). У компании одна открытая заявка. В выданных накладных остаются старые реквизиты.
- Доставщик бывает только у поставщика. На заказ можно назначить только своего доставщика.
- У товара минимум 2 и максимум 5 фото.
- Номер заказа сквозной (№ 0221). Накладные нумеруются у каждого поставщика отдельно, с начала года (2026-00001).
- Статусы заказа:
  - новый → в работе: нужны дата доставки и доставщик; магазин не заблокирован; доставщик активен;
  - новый → отказ: нужна причина;
  - в работе → доставлен: отмечает только назначенный доставщик, по QR; «Отметить доставленным» доступно, только если доставка по QR выключена;
  - в работе → отказ: только команда Zakup.KG.
- Завершённый заказ не меняется. Цена и название в заказе — снимок на момент заказа.
- Флаги `orders_on` и `urgent_on` проверяются при создании заказа.
- Каталог показывает только товары в наличии, не скрытые модератором, от работающих поставщиков (`catalog`). Поиск показывает и товары «Нет в наличии» (`catalog_search`).
- Блокировка компании сразу завершает все сеансы её сотрудников.
- Выдача пароля администратором ставит «сменить пароль при входе», завершает сеансы и пишется в журнал.
- Обращение в поддержку: у пользователя одно открытое, следующее сообщение после закрытия открывает новое.
- Новая версия документа попадает в `users_need_reaccept`: приложение показывает окно «Обновлены правила».

## Доступ

- Приложение работает под ролью `zakup_api`. В каждой транзакции API ставит `SET LOCAL app.user_id`, и база сама ограничивает строки:
  - магазин видит свои заказы;
  - поставщик видит заказы к нему;
  - доставщик видит только назначенные ему;
  - уведомления и корзина видны только своему пользователю.
- Админка работает под ролью `zakup_admin`.
- Журнал, сотрудники, сеансы и запросы по данным приложению недоступны.
- В админке телефоны маскируются: `+996 700 •• •• 01`. Полный номер открывается отдельным действием, которое пишется в журнал.

## Что хранится не в базе

- Пароли хранятся только как хэш argon2id. Хэш считает API, а не база.
- Токены сеансов хранятся как sha256.
- Фото, логотипы и PDF накладных лежат в файловом хранилище. В базе только путь к файлу.
- Сервер и резервные копии с персональными данными должны стоять в КР (Цифровой кодекс, ст. 31 ч. 5 и ст. 89). Иначе нужно отдельное согласие на передачу за рубеж.

## Демо-данные

- Компании, товары, заказы 0212–0221, доставщики, обращения и журнал взяты из макета.
- Телефоны вымышленные: 996 700 000 0xx.
- Хэш пароля — заглушка.
